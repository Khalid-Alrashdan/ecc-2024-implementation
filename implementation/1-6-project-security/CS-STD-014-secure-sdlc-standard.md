# معيار الأمن السيبراني في إدارة المشاريع والتغيير ودورة تطوير البرمجيات

## الغرض

يحدد هذا المعيار متطلبات الأمن السيبراني الواجب استيفاؤها في مشاريع شركة نَسَق للحلول الرقمية والتغييرات على أصولها، وفي دورة تطوير البرمجيات، بحيث يُبنى الأمن داخل المنتج لا يُضاف إليه بعد إنجازه، ويُعدّ مخرَجاً من حزمة العمل WP-19.

## النطاق

جميع المشاريع المعلوماتية والتقنية، والتغييرات على الأصول، ومشاريع تطوير التطبيقات، وخطوط البناء والنشر الثلاثة والعشرين، وواجهات التكامل مع الجهات العميلة والأطراف الخارجية.

## المرجعية

| المرجع | العلاقة |
|---|---|
| ECC-2:2024 — المكوّن الفرعي 1-6 | الضوابط التي يستوفيها هذا المعيار |
| معيار تحصين الأنظمة CS-STD-012 | مراجعة الإعدادات والتحصين قبل الإطلاق |
| معيار إدارة الثغرات CS-STD-008 | تقييم ومعالجة الثغرات في دورة المشروع |
| معيار حماية تطبيقات الويب CS-STD-010 | بوابات الإطلاق الأمنية |
| إجراءات إدارة المخاطر CS-PRO-001 | الحالتان الأولى والرابعة الإلزاميتان للتقييم |

## المبدأ الحاكم

**الضابط المدمج في خط النشر يُنفَّذ دائماً، والضابط المفروض يدوياً يُتجاوَز عند الضغط.** لذلك تُؤتمت جميع الفحوص الممكنة داخل خطوط البناء والنشر بدل الاعتماد على مراجعات يدوية قبل الإطلاق.

## أولاً: الأمن السيبراني في دورة حياة المشروع

| المرحلة | المتطلب | المخرج |
|---|---|---|
| الفكرة والتخطيط | تقييم مخاطر مبكر قبل اعتماد التصميم الفني | تقرير تقييم مخاطر المشروع |
| التصميم | مراجعة أمنية للتصميم ونمذجة التهديدات للمشاريع الحرجة | محضر مراجعة التصميم |
| التطوير | تطبيق معايير التطوير الآمن · فحص آلي مستمر | تقارير الفحص |
| الاختبار | اختبارات أمنية للتحقق من استيفاء المتطلبات | تقرير الاختبارات الأمنية |
| ما قبل الإطلاق | مراجعة الإعدادات والتحصين وحزم التحديثات · إغلاق الثغرات الحرجة والعالية | تقرير جاهزية الإطلاق |
| الإطلاق | تقييم مخاطر الإطلاق واعتماده | قرار إطلاق موثق |
| بعد الإطلاق | مراجعة دورية للإعدادات والتحصين | تقارير المراجعة الدورية |

**قاعدة توقف:** لا يُعتمد التصميم الفني لأي مشروع قبل اعتماد خطة معالجة مخاطره الحرجة والعالية، ولا يُطلق مشروع قبل إغلاق ثغراته الحرجة والعالية.

## ثانياً: إدارة التغيير

| نوع التغيير | المتطلب |
|---|---|
| تغيير جوهري | تقييم مخاطر مرفق بطلب التغيير · مراجعة إعدادات وتحصين · خطة تراجع مختبَرة |
| تغيير معتاد | فحص آلي في خط النشر · مراجعة أقران للكود |
| تغيير طارئ | تنفيذ فوري مع توثيق لاحق خلال يوم عمل ومراجعة أمنية بأثر رجعي |

- لا يُنفَّذ تغيير على بيئة الإنتاج خارج خط النشر المعتمد، ويُعدّ التغيير اليدوي المباشر مخالفة.
- تُراجَع الإعدادات والتحصين وحزم التحديثات قبل كل إطلاق أو تدشين، وتُوثَّق النتيجة.
- يُحتفظ بسجل كامل للتغييرات يربط كل تغيير بمن اعتمده ومن نفّذه ومتى.

## ثالثاً: معايير التطوير الآمن

| المجال | المتطلب |
|---|---|
| التحقق من المدخلات | التحقق من جانب الخادم إلزامي · قوائم سماح لا قوائم حظر |
| الاستعلامات | استعلامات معاملية إلزامية · يُمنع تركيب الاستعلامات نصياً |
| ترميز المخرجات | ترميز كل مخرج بحسب سياق عرضه |
| المصادقة والتفويض | تحقق على مستوى كل طلب · لا اعتماد على إخفاء المسارات |
| إدارة الأسرار | من خزنة الأسرار حصراً وفق CS-PRO-004 |
| التسجيل | تسجيل العمليات الحساسة دون تسجيل بيانات حساسة |
| معالجة الأخطاء | رسائل عامة للمستخدم · تفاصيل في السجلات فقط |
| التبعيات | مكتبات من مصادر موثوقة ومرخصة فقط |
| مراجعة الأقران | مراجعة إلزامية قبل الدمج في الفروع الرئيسية |

## رابعاً: أدوات التطوير والمكتبات

| المتطلب | التفصيل |
|---|---|
| المصادر | أدوات ومكتبات من مصادر مرخصة وموثوقة فقط · يُمنع التحميل من مصادر غير معتمدة |
| المستودع الداخلي | تُسحب المكتبات عبر مستودع الحزم الداخلي لا مباشرةً من الإنترنت |
| قائمة المكوّنات | قائمة محدَّثة لكل نظام تحصر مكتباته وإصداراتها وتراخيصها |
| الفحص | فحص المكتبات آلياً مع كل بناء وشهرياً على التاريخ الكامل |
| التراخيص | التحقق من توافق ترخيص كل مكتبة مع استخدامها التجاري |
| المكتبات غير المصانة | حظر إدخال مكتبة لم تُصان خلال ١٨ شهراً · خطة إحلال للقائم منها |

## سادساً: أمن التكامل بين التطبيقات

| المتطلب | التفصيل |
|---|---|
| المسار | كل تكامل عبر بوابة الواجهات البرمجية · يُمنع التكامل المباشر بين التطبيقات |
| المصادقة | مصادقة متبادلة بين الطرفين · لا اعتماد على عنوان الشبكة وحده |
| التفويض | صلاحية محددة لكل تكامل بأدنى نطاق ممكن |
| التشفير | إلزامي في جميع مسارات التكامل الداخلية والخارجية |
| التحقق من البيانات | تحقق من صحة البيانات الواردة من الطرف الآخر قبل معالجتها |
| الحد من المعدل | حماية من الاستهلاك المفرط أو الإساءة |
| التسجيل | تسجيل كل استدعاء تكامل مع معرّف الطرف والنتيجة |
| الاختبار | اختبار أمني للتكامل قبل تفعيله في الإنتاج |

**يُمنع الثقة الضمنية:** لا يُفترض أن الطرف المتكامل آمن لمجرد أنه داخلي أو تابع لجهة عميلة، ويُطبَّق التحقق على كل استدعاء.

## المراجعة والتحديث

يُراجَع هذا المعيار سنوياً على الأقل، وعند تغيّر أدوات التطوير أو منهجية إدارة المشاريع. وتُراجَع متطلبات الأمن السيبراني في إدارة المشاريع دورياً ويُوثَّق إثبات المراجعة. وتُوثَّق التغييرات وتُعتمد من صاحب الصلاحية.
